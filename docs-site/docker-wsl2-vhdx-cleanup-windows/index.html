Docker and WSL2 VHDX cleanup on Windows

Deleting images or files inside Docker Desktop or WSL2 does not shrink the ext4.vhdx virtual disk on Windows, so you have to compact it: run wsl --shutdown, then compact the VHDX with diskpart (or Optimize-VHD where available). SpaceOps helps by locating the virtual disks on your drive and showing how large they are.

Updated 2026-10-16 · SpaceOps v0.x · Windows only

Why does ext4.vhdx stay large?

WSL2 and Docker Desktop store Linux data in a dynamically expanding virtual hard disk. When you delete data inside Linux, the Windows host file keeps its high-water mark until the disk is compacted.

Where is the VHDX file?

SpaceOps' developer-storage reference lists these common locations. They vary by version, so confirm with a scan.

  • Docker Desktop (WSL2 backend): %LOCALAPPDATA%\Docker\wsl\data\ext4.vhdx
  • WSL distributions: %LOCALAPPDATA%\Packages\<Distro>\LocalState\ext4.vhdx

Scan the drive in SpaceOps and search ext:vhdx size:>1GB to see every virtual disk and its size.

How do I shrink the VHDX?

  1. Free space inside first: remove unused Docker images and containers (for example docker system prune) or delete files in your WSL distribution.
  2. Shut down WSL: run wsl --shutdown in PowerShell so the disk is not in use.
  3. Back up anything you cannot recreate; compaction is generally safe, but a backup costs little.
  4. Compact the disk using diskpart, as shown below.
  5. Restart WSL or Docker Desktop and confirm everything works.
wsl --shutdown
diskpart
  select vdisk file="C:\Users\you\AppData\Local\Docker\wsl\data\ext4.vhdx"
  attach vdisk readonly
  compact vdisk
  detach vdisk
  exit

On Windows editions with Hyper-V tools, Optimize-VHD -Path <file> -Mode Full does the same job. Recent WSL versions may also offer sparse disks via wsl --manage <distro> --set-sparse true; check wsl --help for what your version supports.

Never delete ext4.vhdx to free space. That file is the Linux filesystem, so deleting it destroys the distribution or Docker data. SpaceOps classifies virtual disks as high risk and leaves them unselected by default.

Frequently asked questions

Why did my disk not free up after deleting Docker images?

The VHDX only grows on the host; it does not shrink automatically. Compact it after shutting down WSL.

Is it safe to compact a VHDX?

Compaction only reclaims unused blocks, but always stop WSL first and keep a backup of anything important.

Can SpaceOps compact the VHDX for me?

SpaceOps locates and sizes the virtual disks and points you to the safe steps. The commands above are the standard Windows tools, which you run yourself.

Where is my Docker Desktop disk?

Common locations are listed above, but they vary by Docker Desktop version. A SpaceOps scan with the filter ext:vhdx finds them wherever they are.

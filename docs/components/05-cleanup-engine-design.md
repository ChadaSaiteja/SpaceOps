# Cleanup Engine & Safety Architecture — Component Design

Status: **Approved design for Phase 6.**

Governed by: ADR-001 (FFI), ADR-003 (module boundaries), ADR-007 (threading), ADR-009 (StorageTree arena), ADR-012 (Search Engine), ADR-013 (Cleanup Safety Architecture), PRD §12 (Cleanup System).

---

## 1. Problem Statement

Windows users regularly lose gigabytes to accumulated temporary files, Windows Update download residue, thumbnail caches, minidumps, and browser caches. However, traditional disk cleaners pose severe risks: deleting active system binaries, corrupting user profiles, or destroying uncommitted files.

The **Storage Intelligence Cleanup Engine** solves this by establishing a **Zero-Accident Safety Model**:
1. Every candidate must explain **what it is**, **where it is**, **how much space it uses**, **why it can be removed**, **consequences of removal**, and **risk level**.
2. Deletions default to the **Windows Recycle Bin** (`FOF_ALLOWUNDO`), providing a safety net against accidental removal.
3. Every operation supports a **Dry-Run Mode** to audit reclaimable space and locked files without modifying the disk.
4. Hardcoded **Protected System Locations** cannot be deleted under any circumstance.

---

## 2. Safety Model & Invariants

### Invariant 1: Protected Locations (Immutable Blacklist)
The engine strictly rejects any deletion targeting or encompassing protected roots:
- Drive roots (`C:\`, `D:\`, etc.)
- Windows System: `%SystemRoot%` (`C:\Windows`), `System32`, `SysWOW64`, `WinSxS`, `Boot`
- Program Directories: `C:\Program Files`, `C:\Program Files (x86)` (wholesale directory deletion prohibited)
- User Profile Root & Core Libraries: `%USERPROFILE%`, `Desktop`, `Documents`, `Downloads`, `Pictures`, `Music`, `Videos`
- System State: Pagefile (`pagefile.sys`), Swapfile (`swapfile.sys`), Hiberfil (`hiberfil.sys`)

### Invariant 2: Windows Shell Recycle Bin by Default
All deletions utilize Windows Shell `IFileOperation` / `SHFileOperationW` with `FO_DELETE` and `FOF_ALLOWUNDO`. Files are sent to the Recycle Bin so users can restore them if needed. Permanent deletion (`FOF_ALLOWUNDO` omitted) is only allowed when explicitly toggled by user confirmation for Recycle Bin purging.

### Invariant 3: Dry-Run Auditing
Before performing any modification, the cleanup engine can run in **Simulation Mode** (`dry_run = true`):
- Resolves all targeted files.
- Inspects file attributes and sharing flags (detecting in-use/locked files).
- Returns the exact byte count and file count that would be reclaimed without touching the disk.

### Invariant 4: Transparent Explanations (PRD §12)
Every cleanup candidate struct exposes:
- `id`: Unique identifier (e.g. `user_temp`, `windows_update`, `crash_dumps`).
- `name`: Human-readable label (e.g. *User Temporary Files*).
- `description`: Explains what the files are.
- `path_display`: Display path (e.g. `%LOCALAPPDATA%\Temp`).
- `reason`: Why these files accumulated and can be safely deleted.
- `consequence`: What happens after deletion (e.g. *Applications will recreate temporary files as needed*).
- `risk_level`: `Low`, `Medium`, or `High`.
- `total_bytes`: Reclaimable bytes computed from `StorageTree` or fast query.
- `file_count`: Total files targeted.

## 3. Candidate Rule Catalog

| Rule ID | Category | Target Location(s) | Risk Level | Description |
| :--- | :--- | :--- | :--- | :--- |
| `user_temp` | Temporary Files | `%TEMP%`, `%LOCALAPPDATA%\Temp` | 🟢 Low | Temporary files generated by running applications. Older than 24h. |
| `system_temp` | Temporary Files | `C:\Windows\Temp` | 🟢 Low | System-level temporary files created by Windows services. |
| `update_download`| Windows Update | `C:\Windows\SoftwareDistribution\Download` | 🟡 Medium | Staged installation packages for updates already applied. |
| `crash_dumps` | Diagnostics | `C:\Windows\Minidump`, `%LOCALAPPDATA%\CrashDumps`, `C:\Windows\MEMORY.DMP` | 🟢 Low | Crash memory dumps from past application/system crashes. |
| `thumbcache` | System Cache | `%LOCALAPPDATA%\Microsoft\Windows\Explorer\thumbcache_*.db` | 🟢 Low | Cached thumbnail images; Windows rebuilds them on demand. |
| `recycle_bin` | Recycle Bin | Per-drive `$Recycle.Bin` | 🟢 Low | Files deleted by user currently held in the Recycle Bin. |
| `stale_logs` | Logs & Backups | `*.log`, `*.old`, `*.bak` in temp directories older than 14 days | 🟢 Low | Diagnostic logs no longer needed. |

## 4. FFI & C-ABI Specification

```rust
#[repr(C)]
#[derive(Clone, Copy, Debug, PartialEq)]
pub struct CleanupCandidateFfi {
    pub rule_id: u32,       // 0=UserTemp, 1=SystemTemp, 2=WindowsUpdate, 3=CrashDumps, 4=Thumbcache, 5=RecycleBin, 6=StaleLogs
    pub risk_level: i32,    // 0=Low, 1=Medium, 2=High
    pub total_bytes: u64,
    pub file_count: u64,
    pub is_protected: u8,   // 1 if rule intersects protected area (safety check failed)
}

#[repr(C)]
#[derive(Clone, Copy, Debug, PartialEq)]
pub struct CleanupReportFfi {
    pub files_reclaimed: u64,
    pub bytes_reclaimed: u64,
    pub files_failed: u64,
    pub is_dry_run: u8,
}
```

Functions:
- `cleanup_detect_candidates(tree_handle, out_candidates, limit, out_count)`: Scans in-memory tree or filesystem paths for candidate categories and aggregates reclaimable bytes.
- `cleanup_execute_rule(rule_id, dry_run, send_to_recycle_bin, out_report)`: Executes safe removal or dry-run simulation for the given rule category.
